## 1. OBS-01 trades — `l1-trade-post04d.obs01.jsonl`

### Envelope structure
The envelope wraps a `payload` object. Trade-specific fields live **inside** `payload`. Top-level has only routing metadata.

```json
{
  "event_id": "trade-rithmic-post04d-full-000000000001",
  "run_id": "rithmic-post04d-full",
  "schema_version": 1,
  "session_id": "mnq-2026-04-27-rth",
  "ts_ns": "1777301422098008205",
  "type": "TRADE",
  "payload": {
    "aggressor_side": "sell",
    "exchange_event_ts_ns": "1777301422098008205",
    "sidecar_recv_ts_ns": "1777301421596955300",
    "price": 27381.25,
    "quantity": 1,
    "trade_id": "6875892387204"
  }
}
```

### Field reference

| Field | Location | Type | Notes |
|---|---|---|---|
| `event_id` | top | string | Unique per envelope. Sequential within a run. |
| `run_id` | top | string | Capture-run identifier (matches the probe's `--run-id` or auto-generated) |
| `schema_version` | top | int | Currently 1. Bump on incompatible changes. |
| `session_id` | top | string | Format `mnq-YYYY-MM-DD-rth` or `-globex`. Generated by `session/session_clock.py`. |
| `ts_ns` | top | string (decimal ns) | Equal to `payload.exchange_event_ts_ns` for TRADE events. |
| `type` | top | string | `"TRADE"` for trade events; also `"QUOTE"` exists (small count, ~336 in fixture). |
| `aggressor_side` | payload | string | `"buy"`, `"sell"`, occasionally `"unknown"`. ≥99% populated. |
| `exchange_event_ts_ns` | payload | string (decimal ns) | **Canonical timestamp.** Use this for binning. |
| `sidecar_recv_ts_ns` | payload | string (decimal ns) | Host receipt time. **Do not use for analytics binning.** |
| `price` | payload | float | Tick-aligned (0.25 increments for MNQ). |
| `quantity` | payload | int | Per-trade contract count. |
| `trade_id` | payload | string | Exchange-assigned trade identifier. |

### Distribution in fixture
- 104,358 TRADE events + 336 QUOTE events = 104,694 total
- Aggressor balance: 50,657 buys / 53,701 sells (close to balanced)
- All prices in 27,200–27,600 range (a quiet RTH window)

### Loader contract (RA-002)
`load_obs01_trades` must:
1. Stream the file (don't load all into memory)
2. Filter to `type == "TRADE"`
3. Flatten `payload.*` into top-level columns
4. Rename `exchange_event_ts_ns → event_ts_ns` and `sidecar_recv_ts_ns → recv_ts_ns`
5. Cast decimal strings to int64 (ns timestamps)
6. Compute `signed_qty = quantity × {+1 if aggressor=buy, −1 if sell, 0 if unknown}`
7. Cast `aggressor_side` to pandas Categorical

## 2. MBP1 — `databento/MNQM6_mbp1_post04d.normalized.jsonl`

### Schema (Databento-flat, no nesting)

```json
{
  "ts_event_ns": "1777301362082830655",
  "ts_recv_ns": "1777301362082920202",
  "bid_px_00": 27371.25,
  "bid_sz_00": 6,
  "bid_ct_00": 6,
  "ask_px_00": 27371.75,
  "ask_sz_00": 8,
  "ask_ct_00": 8
}
```

8 fields per record. `_00` suffix = top of book (level 0).

### Field reference

| Field | Type | Notes |
|---|---|---|
| `ts_event_ns` | string (decimal ns) | Exchange timestamp. **Canonical.** |
| `ts_recv_ns` | string (decimal ns) | Host receipt timestamp. |
| `bid_px_00` | float | Best bid price |
| `bid_sz_00` | int | Cumulative size at best bid |
| `bid_ct_00` | int | Number of resting orders at best bid (queue depth) |
| `ask_px_00` | float | Best ask price |
| `ask_sz_00` | int | Cumulative size at best ask |
| `ask_ct_00` | int | Number of resting orders at best ask |

### Quality
- Zero nulls observed across the fixture
- Tick-by-tick (~2M updates in 37 min = ~900 updates/second average)

## 3. MBP10 — `databento/MNQM6_mbp10_post04d.normalized.jsonl`

### Schema (60 fields, Databento-flat)

Same shape as MBP1 but with levels `_00` through `_09` for both sides. Three triples per level: `_px_NN`, `_sz_NN`, `_ct_NN`.

```json
{
  "ts_event_ns": "...", "ts_recv_ns": "...",
  "bid_px_00": ..., "bid_sz_00": ..., "bid_ct_00": ...,
  "ask_px_00": ..., "ask_sz_00": ..., "ask_ct_00": ...,
  ...
  "bid_px_09": ..., "bid_sz_09": ..., "bid_ct_09": ...,
  "ask_px_09": ..., "ask_sz_09": ..., "ask_ct_09": ...
}
```

### Quality
- **Zero nulls** across all 10 levels of all 2.79M records — exceptional data quality
- 2.69 GB / 37 min = ~870 KB/sec (huge; this is why MBP10 is opt-in for lean stack)

## 4. MBO — `databento/MNQM6_mbo_post04d.normalized.jsonl`

### Schema (per-order events, Databento-flat)

```json
{
  "ts_event_ns": "1777301362082830655",
  "ts_recv_ns": "1777301362082920202",
  "sequence": "42788187",
  "action": "C",
  "side": "B",
  "price": 27371.25,
  "size": 1,
  "order_id": "6875892301191"
}
```

### Field reference

| Field | Type | Values | Notes |
|---|---|---|---|
| `ts_event_ns` | string ns | — | **Canonical timestamp.** |
| `ts_recv_ns` | string ns | — | Host receipt. |
| `sequence` | string int | — | Monotonic per-stream; use for gap detection. |
| `action` | string char | `A` (add), `M` (modify), `C` (cancel), `F` (fill), `T` (trade/clear) | A and C dominate. |
| `side` | string char | `B` (bid), `A` (ask) | |
| `price` | float | — | Order price (NaN possible on T/clear events). |
| `size` | int | — | Order size at time of event. |
| `order_id` | string | — | Provider-assigned. Trackable across A→M→C lifecycle. |

### Action distribution in fixture
- Add (A): 1,369,723 (43%)
- Cancel (C): 1,369,849 (43%)
- Modify (M): 246,806 (8%)
- Fill (F): 109,546 (3%)
- Trade (T): 63,667 (2%)

The near-equal A/C count is textbook fingerprint of a healthy MBO feed.

### Quality
- 3.16M events / 37 min = ~1,400 events/sec
- 520 MB raw; gzip compresses ~5–8× → ~70–100 MB compressed

## Loader patterns

For streaming large MBO/MBP10 files efficiently in pandas:

```python
import pandas as pd
import json
from pathlib import Path

def stream_jsonl(path: Path, chunk_size: int = 10_000):
    """Yield DataFrames of chunk_size rows from a JSONL file."""
    rows = []
    with path.open("r", encoding="utf-8") as f:
        for line in f:
            rows.append(json.loads(line))
            if len(rows) >= chunk_size:
                yield pd.DataFrame(rows)
                rows = []
    if rows:
        yield pd.DataFrame(rows)
```

For OBS-01, the `type` filter is critical — drop QUOTE rows before flattening payload:

```python
def load_obs01_trades(path: Path) -> pd.DataFrame:
    rows = []
    with path.open("r", encoding="utf-8") as f:
        for line in f:
            rec = json.loads(line)
            if rec.get("type") != "TRADE":
                continue
            payload = rec.get("payload", {})
            rows.append({
                "event_ts_ns": int(payload["exchange_event_ts_ns"]),
                "recv_ts_ns": int(payload["sidecar_recv_ts_ns"]),
                "session_id": rec["session_id"],
                "price": float(payload["price"]),
                "quantity": int(payload["quantity"]),
                "aggressor_side": payload["aggressor_side"],
                "trade_id": payload["trade_id"],
            })
    df = pd.DataFrame(rows)
    df["aggressor_side"] = df["aggressor_side"].astype("category")
    sign = df["aggressor_side"].map({"buy": 1, "sell": -1}).fillna(0).astype("int32")
    df["signed_qty"] = (df["quantity"] * sign).astype("int32")
    return df
```

This is the canonical loader shape; engineer is free to optimize (chunked streaming, polars, pyarrow) but the semantics must match.

## Validation tips

For sanity-checking a fresh capture:
- `wc -l <file>` — line count sanity
- `head -1 <file> | python -m json.tool` — schema sanity
- `grep -c '"type":"TRADE"' obs01.jsonl` — count trades
- `grep -c '"action":"A"' mbo.jsonl` — count adds (should ~match cancels)

For tick-time alignment between OBS-01 and MBP1: `event_ts_ns` of a trade should fall within ±1ms of a corresponding MBP1 update (the price ticked, then the depth updated). Off by more than 10ms suggests a feed issue.
